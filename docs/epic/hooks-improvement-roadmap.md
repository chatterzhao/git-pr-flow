# Epic14: Git Hooks改进 - 路线图

## 概述

改进GPF的git hooks系统，支持非交互式强制提交功能，解决在特殊情况下需要跳过工作流保护的需求，同时保持整体工作流的安全性和一致性。

## 问题分析

### 核心问题
在GPF开发过程中发现的hooks限制问题：

1. **过于严格的工作流保护**:
   - Epic分支完全禁止提交，包括必要的管理文件
   - 无法在紧急情况下进行修复提交
   - 阻碍了Epic级别的配置和文档管理

2. **缺乏灵活性**:
   - 没有强制提交的安全通道
   - 无法处理特殊的开发场景
   - 过度依赖严格的分支策略

3. **非交互式环境支持不足**:
   - AI用户和自动化脚本无法处理hooks阻塞
   - 缺乏程序化的工作流控制
   - 紧急修复时的操作复杂

## 解决方案

### 已完成的工作 ✅

#### 功能分支: force-commit-support
**实现内容**:

1. **强制提交机制**:
   - 添加 `GPF_FORCE_COMMIT` 环境变量支持
   - 两种使用方式：
     - `GPF_FORCE_COMMIT=1 git commit -m "message"`
     - `git commit -m "message GPF_FORCE_COMMIT"`

2. **Enhanced pre-commit hook**:
   ```bash
   # 检查强制提交标志
   if [[ -n "${GPF_FORCE_COMMIT:-}" ]] || [[ "$commit_msg" == *"GPF_FORCE_COMMIT"* ]]; then
       echo "⚠️  GPF工作流保护已被强制跳过 (GPF_FORCE_COMMIT)"
       echo "📝 提交分支: $(git branch --show-current)"
       exit 0
   fi
   ```

3. **安全性保证**:
   - 强制提交时显示明确的警告信息
   - 记录当前分支信息
   - 保持其他工作流保护不变

4. **用户体验优化**:
   - 清晰的错误提示和使用指导
   - 提供两种便捷的强制提交方式
   - 维持正常工作流的完整性

### 技术实现细节

#### Hook逻辑增强
```bash
#!/bin/bash
# Enhanced pre-commit hook with force commit support

check_force_commit() {
    local commit_msg_file="$1"
    local commit_msg=""
    
    if [[ -f "$commit_msg_file" ]]; then
        commit_msg=$(cat "$commit_msg_file")
    fi
    
    # 检查环境变量
    if [[ -n "${GPF_FORCE_COMMIT:-}" ]]; then
        return 0
    fi
    
    # 检查提交信息
    if [[ "$commit_msg" == *"GPF_FORCE_COMMIT"* ]]; then
        return 0
    fi
    
    return 1
}

# 主要逻辑
if check_force_commit "$1"; then
    echo "⚠️  GPF工作流保护已被强制跳过 (GPF_FORCE_COMMIT)"
    echo "📝 提交分支: $(git branch --show-current)"
    exit 0
fi

# 继续正常的工作流检查...
```

#### 工作流保护策略
- **Epic分支**: 默认禁止提交，可强制提交
- **功能分支**: 允许正常开发提交
- **主分支**: 严格保护，建议避免强制提交

## 使用场景

### 适合强制提交的场景
1. **Epic级别配置**: Epic分支的配置文件修改
2. **紧急修复**: 关键bug的紧急修复
3. **文档更新**: Epic roadmap等管理文档
4. **自动化流程**: CI/CD或脚本自动提交

### 不建议强制提交的场景
1. **常规功能开发**: 应在功能分支进行
2. **主分支提交**: 应通过PR流程
3. **未经测试的代码**: 应先验证再提交
