# clean-command-optimization

## 本epic的职责:

优化 `gpf clean` 命令的用户体验和安全性，实现智能化的环境清理机制，减少操作步骤，增强安全保护。

### 🚨 当前问题分析：

1. **无引导问题**：无参数时只显示状态，不提示如何进行清理
2. **操作繁琐**：需要分别执行多个清理命令（worktrees、branches、epic等）
3. **缺乏安全检查**：没有自动检测未提交、未合并等阻断条件
4. **缺少强制选项**：无法处理测试环境等需要强制清理的场景
5. **用户体验差**：需要记住各种参数，缺乏智能引导

### 🎯 改进目标：

- [ ] **智能引导**：无参数时提供清晰的操作指引和建议
- [ ] **批量清理**：`--all` 参数实现一键安全清理所有资源
- [ ] **安全检查**：自动检测并阻止有风险的清理操作
- [ ] **强制清理**：`--force` 参数支持强制清理测试环境
- [ ] **预览功能**：`--dry-run` 参数预览清理计划
- [ ] **分级显示**：按风险级别分类显示清理项目

## 🎨 设计理念

### 智能引导优先
无参数时不应该静默展示状态，而应该：
```bash
gpf clean
# 应该显示：
📋 环境分析完成
🟢 可安全清理：2个工作树, 3个已合并分支
🟡 需要注意：1个未推送分支  
🔴 阻断条件：1个有未提交更改的工作树

💡 推荐操作：
  gpf clean --all          # 清理所有安全资源
  gpf clean --all --force  # 强制清理所有资源（谨慎使用）
  gpf clean --dry-run      # 预览完整清理计划
```

### 安全第一
- 默认只清理确认安全的资源
- 明确标识风险项目
- 提供撤销和恢复建议
- `--force` 需要二次确认

### 操作便利性
- 一键清理：`gpf clean --all`
- 预览功能：`--dry-run`
- 智能建议：根据环境状态提供最佳操作方案

## 🚀 使用场景示例

### 场景1：正常开发后清理
```bash
# 用户想清理环境
gpf clean

# 系统分析并显示：
📋 环境分析完成
🟢 可安全清理：2个已合并分支, 1个未使用工作树
💡 推荐：gpf clean --all

# 用户执行
gpf clean --all
# 一键清理所有安全资源
```

### 场景2：测试环境强制清理
```bash
# 测试后有未提交更改
gpf clean

# 系统显示：
🔴 阻断条件：1个工作树有未提交更改
💡 解决方案：
  git add . && git commit -m "test changes"  # 提交更改
  gpf clean --all --force                   # 强制清理（丢失更改）

# 测试环境，用户选择强制清理
gpf clean --all --force
# 二次确认后强制清理
```

### 场景3：预览清理计划
```bash
# 用户想了解清理影响
gpf clean --dry-run

# 系统显示详细计划：
📋 清理计划预览
🟢 将删除工作树：epic--test (安全)
🟢 将删除分支：test/feature1 (已合并)
🟡 将保留分支：feature/login (未推送提交)
```
